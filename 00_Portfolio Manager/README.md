# Portfolio Manager

Статический сайт по четырём утверждённым чёрно-золотым макетам. Откройте `index.html` двойным нажатием. Установка, сборка, сервер и API-ключи для работы не нужны. Для тестового HTTP-предпросмотра: `python -m http.server 8765 --bind 127.0.0.1` из папки сайта.

## Четыре страницы

- `index.html` — состав, стоимость, результат за доступный период, свободные USD, выплаты и контроль портфеля.
- `positions.html` — полные тикеры, количество, средняя цена, цена источника, стоимость, доля, P/L, поиск, сортировка и CSV.
- `dividends.html` — фактические месяцы за весь доступный период, выбор года, налоги, связанные ADR-сборы, история и CSV. Карточка ближайших выплат сохранена; при отсутствии подтверждённых данных показана соответствующая пометка.
- `transactions.html` — журнал всех доступных сделок, конвертаций, пополнений, дивидендов, налогов, сборов и процентов. Фильтры дат и типа, поиск по тикеру, страницы, детали и CSV.

Везде доступны **0104 / 3251 / Iris / Мои вместе**. «Мои вместе» объединяет только 0104 и 3251. Одинаковые полные тикеры объединяются с суммированием количества, стоимости, себестоимости и P/L. Средняя цена считается по общей себестоимости и количеству. У позиций и операций можно увидеть исходный счёт.

## Периоды и суммы

Снимок позиций и NAV — 16.10.2026 для 0104 и 3251. Iris — два скриншота от 15.10.2026 по именам файлов.

| Режим | Доступная история | NAV USD | Свободно USD |
|---|---|---:|---:|
| 0104 | 15.10.2025–16.10.2026 | 29 561,93 | 89,43 |
| 3251 | 02.01.2026–16.10.2026 | 12 526,58 | 66,95 |
| Мои вместе | Сумма двух счетов с указанными выше периодами | 42 088,51 | 156,38 |
| Iris | Снимки, без истории сделок и выплат | 12 351,36 | 126,86 |

**Свободные средства — только USD Cash. Шекели не включаются.** NAV остаётся полной стоимостью из брокерского отчёта; другой валютный остаток не выдаётся за свободные доллары. На диаграмме он отдельно обозначен «Остаток в NAV» для правильной сверки.

История 0104 взята из полного отчёта по 15.10.2026 и дополнена последним днём свежего отчёта. Пересекающиеся записи не складываются. Доходность 0104 за полный период ≈20,89%: TWR 25,02% из полного отчёта по 15 октября соединена с изменением NAV за 16 октября, когда внешних денежных потоков не было. Знак ≈ отражает округление исходной TWR. Для 3251 TWR 6,10% переписана из отчёта за его период. Единой TWR для «Мои вместе» нет: проценты разных счетов не суммируются и не усредняются.

Прибыль за период = конечный NAV − начальный NAV − чистые пополнения. В «Мои вместе» показывается сумма результатов двух счетов за их доступные периоды. Графики — только реальные точки из источников, включая начальные остатки; это графики стоимости, а не доходности.

У Iris позиции и баланс сняты с разницей в минуту; различие 2,75 USD обозначено. Отсутствующая история остаётся неизвестной, не нулевой.

## GitHub Pages

Содержимое этой папки подготовлено как корень отдельного репозитория. Загрузите файлы с сохранением структуры и выберите в Pages публикацию из ветки с файлами, каталог `/ (root)`. Для отображения нужны HTML, `.nojekyll`, `assets/` и `data/`. Все пути относительные и работают в подпапке репозитория.

Репозиторий не создавался, сайт не публиковался. JSON содержит реальные финансовые данные; они будут доступны посетителям опубликованного сайта. Исходные PDF и скриншоты в сайт не скопированы.

## Обновление и проверка

```powershell
python -m pip install -r tools/requirements.txt
python tools/extract_reports.py
python tools/check_data.py
```

Скрипт выбирает последний снимок отдельно для каждого из двух счетов, а для истории использует самый длинный период. Исходные папки с отчётами должны оставаться рядом с папкой сайта в текущей структуре проекта. Изменение формата PDF или новые денежные потоки в хвосте, требующие неизвестного курса, требуют отдельной сверки: обработчик не должен выдумывать конвертацию. Iris перенесена вручную; новые снимки нужно отдельно проверить.

Для обновления в GitHub заменяются оба файла `data/portfolio-data.json` и `data/portfolio-data.js`. Подробные источники и методика — в `SOURCES.md` и в окне «Источники и методика» на каждой странице. Полные тикеры используются без обрезки до трёх букв.

`mockups/` — четыре утверждённых макета с условными числами. `assets/mountain-banner.png` — локальный фон, созданный встроенным imagegen; точный запрос в `assets/banner-prompt.txt`. Рабочая версия использует реальные данные. Онлайн-котировки, аналитика, watchlist и редактирование операций пока не добавлены.

## Добавленные страницы и функции

- `ticker.html`: логотип и полный тикер, текущая позиция, разбивка по счетам, сделки и дивиденды, личная заметка. Открывается нажатием тикера.
- `plan.html`: цели в процентах, отклонения, сценарий пополнения USD и пропорциональное распределение доступных долларов. Цели задаёт пользователь; торговые заявки не создаются.
- `performance.html`: реализованный P/L, открытые позиции, выплаты, налоги и комиссии. Комиссии не вычитаются повторно из реализованного результата. Общая TWR счетов не усредняется.
- `watchlist.html`: список наблюдения, цена интереса и причина. Онлайн-цены и уведомления пока не подключены.
- `imports.html`: предпросмотр импорта, проверки и защита от повторов, экспорт данных, резервная копия целей/заметок/наблюдения.
- Общий период: вся история, год/месяц отчёта, свои даты. Фильтрует операции и выплаты, не превращает текущие позиции в исторический снимок. Точная доходность произвольного периода не вычисляется без ежедневных NAV и потоков.
- Логотипы компаний и провайдеров ETF лежат локально в assets/logos/. Источник — favicon соответствующего сайта через Google favicon service; домены в sources.json. Четыре квадрата MSFT воспроизводят предоставленный пример. Сайт не загружает значки извне при просмотре.

### Импорт PDF локально

Из папки сайта запустите `python tools/serve.py`, откройте http://127.0.0.1:8765 и страницу «Данные». Зависимость: `pip install -r tools/requirements.txt`.

PDF IBKR должен сохранять оригинальное имя `U22210104_YYYYMMDD_YYYYMMDD.pdf` или `U23483251_YYYYMMDD_YYYYMMDD.pdf`. Проверяются счёт, период внутри PDF, SHA-256, суммы позиций, NAV, налоги и комиссии. Предпросмотр выполняется во временной папке и ничего не меняет. После «Применить» PDF сохраняется в папку соответствующего счёта, обновляются JSON/JS сайта; предыдущий снимок сохраняется в backups/ (исключено из Git). Новые форматы IBKR могут быть отклонены, если парсер не может надёжно сверить показатели.

GitHub Pages поддерживает импорт готового portfolio-data.json в браузер. Для публикации обновлённого общего снимка замените data/portfolio-data.json и portfolio-data.js в репозитории. Личные настройки хранятся в localStorage отдельно для каждого портфеля; переносите их через резервную копию на странице «Данные». Хранилища file://, localhost и GitHub Pages различаются.

### План портфеля по макетам
Три экрана: общий план, портфель 1 (100000 USD), портфель 2 (25000 USD). Количество и цены берутся из отчётов по счетам 0104 и 3251. Интернет-цены не используются; без цены в отчёте количество до цели недоступно. OTHER и Мои проекты заполняются пользователем как группы акций. Акция учитывается в одной группе. Бюджет и покупки сохраняются в браузере и входят в резервную копию на странице Данные.

### Интернет-цены и список наблюдения
В плане количество акций берётся из отчёта, цены — из Yahoo Finance (regularMarketPrice, время regularMarketTime). Сохранённая интернет-котировка доступна при открытии файла; живое обновление выполняется через tools/serve.py и кнопку Обновить цены на http://127.0.0.1:8765/plan.html. Недоступные цены не заменяются ценами отчёта. tools/market_quotes.py обновляет сохранённый снимок 52 бумаг. Часть котировок может поступать с задержкой.
В Наблюдение добавлены 43 акции из агент-cписок покупок/список.xlsx с портфелем, количеством, средней, BUY и Target. BUY-диапазоны сохранены текстом. Импорт дополняет личные списки один раз для каждого счёта; повторное открытие не добавляет дубли. Пункт Данные удалён из навигации.

### Исправления сохранения и списков
План автоматически сохраняется при каждом вводе в браузер. Через tools/serve.py изменения также записываются в .personal/state.json; файл исключён из Git и закрыт от статической выдачи. Кнопка Сохранить немедленно отправляет запись в файл. Пустая группа в плане равна нулю и не блокирует итоги. Пополнение автоматически распределяется по целевым капиталам после вычета резерва; ручные доли проверяются на превышение бюджета. Рассчитать покупки подбирает целые акции в пределах бюджета и сохраняет купленные, отложенные и вручную добавленные групповые позиции. Наблюдение использует общий редактируемый список pm-watchlist-v2 с группами Портфель 1, Портфель 2, Не куплено; старые списки браузера сохраняются для совместимости.
